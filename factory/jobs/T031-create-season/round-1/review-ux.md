## Findings
- [must-fix] apps/web/src/features/seasons/SeasonsPage.tsx:174 — After `createSeason` succeeds, a failed `listSeasons` sets `status: 'error'` (`SeasonsPage.tsx:180`). The form then shows `season.error.save` ("Could not create the season. Please try again.") at `SeasonsView.tsx:300`, the name has already been cleared (`SeasonsPage.tsx:195`), and an empty list still says "This community has no seasons yet." (`SeasonsView.tsx:155`). Create stays enabled, and editing any field clears the error (`SeasonsPage.tsx:222`). A second submit creates another season. There is no season delete on this screen. Follow `CommunitiesView`: a failed reload is its own state, with copy that the season was created but the list could not be loaded, the empty line hidden, Create disabled, and Try again calling `listSeasons` only. Editing the form must leave that state in place.
- [must-fix] apps/web/src/features/seasons/SeasonsView.tsx:70 — An open season is labelled `Active` plus the bare `dayIndex` (`season.state.active` is "Active" in `apps/web/src/i18n/en.json:106`). Next to the start date, "Active 5" can be read as a length. `state.open` is not shown. `t()` does not interpolate, so use a `t()` prefix such as "Active, day" and then the number ("Active, day 5"). Do not add an answer prompt; answering is a later task. Upcoming ("Upcoming") and ended ("Ended") are already clear.

Checked against the spec, and not a defect: this screen has no edit form and the web client has no season PATCH (`apps/web/src/api/client.ts` exposes list, create, and the suggestion only). Create always posts a new season. A listed row is the name (`dir="auto"`), the stored start date (`dir="ltr"`), and the phase from the server. Once the phase is active or ended, nothing on this page can change that start date or length.

Also checked: the suggest control is `type="button"`, shown only for kind Ramadan, and `applyRamadanSuggestion` fills start date and length only (`SeasonsView.tsx:56`). The hint says the Hijri dates are a suggestion the admin confirms. Submit is blocked while saving or suggesting (`SeasonsView.tsx:139`, `SeasonsPage.tsx:185`). The form is limited to admin and owner. Loading, signed-out, unavailable, and the first-load error each have a next step. Strings go through `t()` and the `season.*` keys are in `en.json`. Inputs have labels, controls are native buttons, links, and fields, loading uses `role="status"`, errors use `role="alert"`, and buttons, fields, and the Seasons link are at least 2.75rem with a visible focus outline. Season CSS uses logical properties; the name stretches and wraps, including Arabic and Ge'ez. This screen does not show an answer or an explanation.
